# 데이터 검증 킷 (data-check-kit)

실증연구에서 결과를 망치는 오류는 대개 모형보다 앞, 즉 **읽기 → 정리 → 결합** 단계에서 생긴다.
이 스킬은 그 단계마다 무엇을 숫자로 확인해야 하는지 정해 두고, 같은 순서로 코드를 짜거나 검토하게 한다.

## 절대 규칙

1. **원자료는 읽기만 한다.** 고친 결과는 새 파일(`data/clean/`)로 저장한다.
2. **판정은 계산으로 한다.** "눈으로 보니 맞다"는 쓰지 않는다. 출력된 숫자를 근거로 적는다.
3. **표본을 바꾸는 연산 바로 뒤에는 점검 셀을 둔다.** 필터·중복 제거·결측 삭제·머지가 모두 해당한다.
4. **실행하지 않은 점검은 `미실행`이라고 적는다.** 건너뛴 것을 통과로 보고하지 않는다.
5. **결과를 보고 표본을 거르지 않는다.** 제외 규칙은 분석 전에 정하고 사유를 기록한다.
6. **코드를 짠 쪽과 검사하는 쪽을 나눈다.** 마지막 감사는 `data-auditor` 에이전트에게 맡긴다(7단계).

## 도구

`scripts/dck.py`에 점검 함수가 있다(pandas만 사용). 사용자의 노트북·스크립트에서 이렇게 불러 쓴다.

```python
import sys; sys.path.append(r"<이 스킬 폴더>/scripts")
import dck
flow = dck.Flow()
```

| 함수 | 단계 | 하는 일 |
|---|---|---|
| `dck.read_csv(path, dtype=...)` | 1 | 인코딩 자동 시도(utf-8 → utf-8-sig → cp949) |
| `dck.profile(df, name, key)` | 1 | 행·열·결측률·고유값·완전중복·경고(선행 0 소실, 결측코드, 공백) |
| `dck.key_check(df, key)` | 1·4 | 결측키·중복키 수와 예시 |
| `dck.code_name_map(df, code, name)` | 2 | 코드↔명칭 1:1 여부 |
| `flow.start / flow.step(before, after, label, reason, expect)` | 4 | 단계별 행 수 기록, 기대값 대조(다르면 멈춤) |
| `dck.merge_audit(left, right, on, how, validate)` | 5 | 관계(1:1·N:1·1:N·N:M) 수, 회계식, 양쪽 매칭률·미매칭 행 수, 키 중복 증폭, 미매칭 목록 |
| `dck.dist(df, cols, by)` + `dck.truncation_flags()` | 6 | 분위수·0비율·최댓값 집중, 절단 의심 신호 |
| `dck.total_check(df, col, official)` | 6 | 합계를 공표값과 대조 |
| `flow.table()` | 8 | 표본 흐름표 |

스킬 폴더 경로를 쓸 수 없는 환경(Colab 등)이면 `dck.py`를 작업 폴더에 복사해 쓴다.

## 작업 순서

### 0단계 — 범위 확인 (코드 쓰기 전에 사용자에게 묻거나 파일에서 확인)
- 원자료 경로, 출처(제공기관·기준시점·내려받은 날짜)
- **분석단위**(한 행이 무엇인가: 사업체·시장·시군구·연도…)
- **키 후보**와 결합 상대 자료
- 확인되지 않은 항목은 추측하지 말고 "확인 필요"로 남긴다.

### 1단계 — 로딩 직후 점검
- 코드 성격 열(지역코드·산업코드·ID)은 `dtype=str`로 읽는다. 숫자로 읽으면 선행 0이 사라진다.
- `dck.profile()`로 행·열·결측·완전중복·경고를 출력한다.
- 원자료 파일 해시(`dck.file_hash`)와 행 수를 기록해 둔다. 나중에 같은 파일인지 대조하는 기준이다.

### 2단계 — 코드체계·명칭 점검
- `dck.code_name_map()`으로 코드와 명칭이 1:1인지 본다.
- **같은 이름, 다른 대상**: 시군구명 '중구'·'서구'·'동구'·'고성군'처럼 여러 상위 단위에 같은 이름이 있다. 이름만으로 키를 만들지 않는다.
- **상위·하위 단위 동시 수록**: 시(市) 합계 행과 그 아래 구(區) 행이 같은 표에 있으면 합산 시 이중 집계된다.
- **합계·소계 행**: '전국', '계', '합계' 같은 행을 찾는다.
- **개편**: 행정구역 개편(예: 2023.7 군위군 경북→대구), 산업분류 차수 변경, 결측값 코드(-9, 999 등).

### 3단계 — 결합 규칙 한 장 (머지 전에)
`references/결합규칙_양식.md`를 채운다. 최소한 다음은 머지 전에 적혀 있어야 한다.
분석단위 · 키 · 결합 방향 · **허용 관계(1:1, N:1)** · **금지 관계(N:M)** · 결합 후 예상 행 수 · 미매칭 처리 원칙 · 제외 규칙.

### 4단계 — 클리닝 실행 (단계마다 기록)
- 표본을 바꾸는 연산마다 `flow.step(before, after, "무엇을", "왜", expect=예상행수)`.
- 값 변환(결측코드 → NaN, 단위 변환, 문자 정리)은 행 수는 그대로지만 바뀐 셀 수를 출력한다.
- 제외한 관측치는 버리지 말고 `data/clean/excluded_*.csv`로 따로 저장한다.

### 5단계 — 결합 회계
- `dck.merge_audit(..., validate="many_to_one")`처럼 3단계에서 허용한 관계를 `validate`로 강제한다. 어기면 pandas가 멈춘다.
- 확인할 숫자: 회계식 일치 여부, 양쪽 매칭률(오른쪽 미매칭은 원자료 기준으로 센다), 키 중복 증폭(1 초과면 행이 복제됨), N:M 수, 양쪽 미매칭 목록.
- **미매칭 목록은 반드시 한 줄씩 읽고 원인을 분류한다**(표기 차이 / 개편 / 상하위 단위 / 실제로 없음).

### 6단계 — 분포·외부 대조
- 핵심 변수에 `dck.dist()` + `dck.truncation_flags()`. 집단(연도·지역)별로도 본다.
- 가능하면 합계를 공표 통계와 `dck.total_check()`로 대조한다.

### 7단계 — 의미 점검 (사람이 답할 질문)
`references/의미점검_질문.md`의 질문에 답을 적는다. 코드로 판정할 수 없는 항목이므로 답이 없으면 "확인 필요"로 둔다.

### 8단계 — 표본 흐름표와 독립 감사
1. `flow.table()`을 출력하고 `data/clean/sample_flow.csv`로 저장한다. 논문·보고서의 표본 서술과 한 줄씩 대응해야 한다.
2. `data-auditor` 에이전트를 호출해 독립 감사를 받는다. 넘길 것: 원자료 경로, 정제본 경로, 결합 규칙 파일, 흐름표.
   에이전트가 설치되지 않은 환경이면 새 대화에서 `agents/data-auditor.md`의 지시문으로 같은 감사를 요청한다.
3. 감사에서 나온 결함은 몇 단계로 되돌아가야 하는지(1·2·3·4단계 또는 원자료 확인) 함께 보고한다.

## 기존 코드를 검토할 때

사용자가 이미 짠 클리닝 코드를 검토해 달라고 하면 코드를 고치기 전에 아래 표를 먼저 채워 보고한다.

| 단계 | 점검 항목 | 코드에 있음 / 없음 / 부분 | 근거(줄 번호) |
|---|---|---|---|

없는 항목은 추가할 점검 셀을 제안한다. 원본 코드는 사용자가 허락하기 전에는 수정하지 않고, 점검 코드는 새 파일로 만든다.

## 보고 형식

- 단계별로 **실행한 코드 → 출력 숫자 → 판정(통과/경고/실패/미실행)** 순으로 적는다.
- 판정 서술어로 세기를 구분한다: "확인되었다"(계산으로 확인) < "추정된다"(간접 근거) < "확인 필요"(근거 없음).
- 결함마다 위치, 유형, 재현 방법, 되돌아갈 단계를 적는다.
